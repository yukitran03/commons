# Commons Implementation Plan

> **Historical.** This is the build plan as written on 2026-11-08, kept for the record. The code has moved on since then: for example it does not use zod, each member account gets 0.5 NEAR (not 0.3), and gas amounts changed. The README describes what the code does today.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Telegram group treasury on NEAR. The money sits in a Sputnik DAO, every member is a named NEAR account whose key stays on their phone, and the bot can propose spends but can never vote or move money.

**Architecture:** A Next.js app (Vercel) hosts the Telegram webhook, a Telegram Mini App and a public ledger. Chain access goes through a `Chain` interface with two implementations: `RpcChain` (near-api-js against testnet) and `FakeChain` (an in-memory model of the Sputnik rules used by tests and the offline demo). Postgres (Neon in production, PGlite locally) only maps Telegram chats and users to NEAR accounts; the chain is the source of truth for money, votes and policy.

**Tech Stack:** Next.js 16, React 19, TypeScript 6 (strict, ESM), near-api-js 7.4, zod 4, @neondatabase/serverless, @electric-sql/pglite, vitest 4, Tailwind 4.

## Spike results (2026-11-08, testnet, verified)

- `helper.nearprotocol.com/account` creates a funded `.testnet` account (10 NEAR) from `{newAccountId, newAccountPublicKey}` without any key.
- `sputnikv2.testnet.create({name, args: base64(JSON({config, policy}))})` with 6 NEAR deposit and 150 Tgas creates `<name>.sputnikv2.testnet` (contract version 2.3.1, storage 544,267 bytes).
- With the roles below, the bot's `act_proposal` and a `ChangePolicy` proposal both fail with `ERR_PERMISSION_DENIED`; 2 of 2 council approvals execute a `Transfer` (tx 2GqwhpUEwZ2WPMRqtqv99JsiYoZZcDKpmHdWk17RUFrH).
- 1Click `POST /v0/quote` timed out server side (HTTP 500 after 25 s) on four attempts; the client must treat a timeout as "quote unavailable", not crash.

## Global Constraints

- Node >= 22. ESM everywhere. Scripts run with `node --experimental-strip-types`.
- near-api-js 7.4.x only. Never near-sdk-js, wallet-selector, Shade Agents or NEAR AI Hub (deprecated).
- Network default `testnet`; factory `sputnikv2.testnet`; explorer `https://testnet.nearblocks.io`.
- DAO creation: deposit 6 NEAR, gas 150 Tgas. `add_proposal`: gas 50 Tgas, deposit = policy `proposal_bond` (0.01 NEAR). `act_proposal`: gas 150 Tgas.
- Council role permissions exactly `["*:VoteApprove","*:VoteReject","*:VoteRemove","*:Finalize","*:AddProposal"]`.
- Bot role name `proposer`, permissions exactly `["transfer:AddProposal","add_member_to_role:AddProposal"]`.
- Vote policy `{weight_kind:"RoleWeight", quorum:"0", threshold:[1,2]}` (needs floor(n/2)+1 of n council members).
- Member private keys are created in the browser and never sent to the server. The server only ever sees public keys.
- New member accounts are `<name>.<SPONSOR_ACCOUNT_ID>` funded with 0.3 NEAR for gas.
- No secrets in the repo: `.env.example` only; test fixtures use obviously fake values.
- User-facing copy is plain and professional: no em dashes, no hype words.
- Commits authored as `yukitran03 <185142272+yukitran03@users.noreply.github.com>`.

## Review Focus

- A Telegram user without a @username joins: the account name falls back to first name plus a short id suffix and is still valid and unique (Task 2 test `accountName falls back without username`).
- `/spend` with a bad amount ("0", "-1", "1,5", "abc", more decimals than the token has) or to someone who is not a member: a clear reply and no proposal (Task 2 parser tests, Task 6 e2e test `spend to non-member is refused`).
- Telegram resends an update or a user taps twice: no second account, no second DAO (Task 6 e2e test `join and create are idempotent`).
- A forged or stale Mini App request (bad hash, missing initData, auth_date older than 24 h): 401 (Task 5 test `rejects forged and stale initData`).
- A vote notification for a proposal that the chain says is still open, or a made-up proposal id: the bot reports only the state it reads from the chain (Task 6 e2e test `vote notify trusts the chain only`).
